01 Flagship Supervised · binary classification

Predicting customer dissatisfaction before the review lands

117,329 order rows assembled from seven joined relational tables of Brazilian marketplace data. The model scores an order at dispatch time using only information available before the customer reviews it, so operations can intervene on the orders most likely to draw a 1–3 star rating.

The decisive finding is operational rather than algorithmic: orders delivered on time satisfy 80.2% of customers, orders delivered late satisfy 26.4%. Delivery lateness alone accounts for the single largest share of model gain.

02 Model selection · ensembles

Nine tree-based classifiers, benchmarked honestly

A controlled comparison on Kaggle's Spaceship Titanic: decision tree, random forest, gradient boosting, XGBoost and LightGBM, plus four voting ensembles — all on one stratified split, then a randomised search and a threshold sweep on the winner.

The write-up is as much about what didn't work: the voting ensembles never beat their best member, and cross-validation accuracy overstated held-out accuracy by 2.7–3.1 points in both tuned configurations.

How the work is done

Four habits that make the numbers trustworthy.

Aggregations computed after the split

Seller and category statistics — average delay, order volume, average freight — are fitted on training rows only and joined onto validation rows with a train-derived fallback. Computing them on the full frame first is the most common silent leak in tabular work, and it inflates scores that then collapse in production. 

X_tr, X_te = train_test_split(X, ...)
stats = X_tr.groupby("seller_id").agg(...)   # train only
X_te  = X_te.merge(stats, how="left").fillna(train_global)

A holdout score is an estimate, not a fact

The e-commerce model scores 0.8057 ROC-AUC, but Optuna chose its parameters on that same holdout, and removing just 15 rows before splitting moves the score to 0.7936. The report states the number with that caveat attached rather than presenting it as exact.

▲ A best-of-n score on the evaluation set is a selection statistic, not a performance estimate.

Thresholds are chosen, not defaulted

0.5 is an arbitrary cut on a class-imbalanced problem. Both projects sweep the decision threshold against the metric that matches the objective — F1 on the minority class for dissatisfaction, accuracy for the Kaggle target — and publish the full sweep so the trade-off is visible rather than asserted.

0.666 · maximises minority F1 0.42 · +0.34 pts accuracy over 0.5

Every published figure is regenerated from the model

Two scripts reload the persisted models, reproduce the exact splits, and write every metric, curve and table on this site to a JSON file the pages read at load. Nothing is transcribed by hand, so the site cannot drift away from the notebooks. 

uv run python tools/gen_supervised_metrics.py
uv run python tools/gen_tree_metrics.py
