Project 02 · Model selection

Nine tree-based classifiers, benchmarked honestly.

Kaggle's Spaceship Titanic asks whether a passenger was transported to another dimension. The interesting part is not the answer — it is running a disciplined comparison where every model sees the same split, and then reporting what the ensembles failed to add.

The benchmark

Every model on the same split, then the ensembles that didn't help.

Five base learners and four voting schemes over four of them, all evaluated on one stratified 20% validation split so the comparison is apples to apples.

◆ The ensembles never won. Weighted hard voting reached 77.77%, just under gradient boosting's 78.05% on its own. Averaging four tree learners that make the same mistakes on the same rows adds computation, not accuracy — the errors are correlated, so there is nothing to cancel.

The 2.7-point CV gap

Every tuned configuration scored substantially better under 5-fold cross-validation than on the held-out split:

Model CV Holdout Gap
Gradient boosting 80.23%77.15% −3.08
LightGBM 80.49%77.84% −2.65

The search picks its winner on the CV score, so that score is a selection statistic and is optimistic by construction. The holdout number is the one worth quoting.

Approach

From raw CSV to a calibrated decision.

Missing data, decided rather than defaulted

Roughly 2% of each column is missing, spread thin. Model-based imputation was tested and reached only ~72% accuracy at predicting the missing categoricals, so it was rejected in favour of an explicit Unknown level for categoricals. In training, rows still missing any value were then dropped — before Cabin and Name were removed, so some rows were lost for gaps in columns deleted a step later. That cost 1,428 of 8,693 passengers. The test set was median-filled instead, so every competition row gets a prediction.

Imputation tried and rejected 16.4% of rows discarded

Two columns removed on principle

Cabin is shared between passengers, so it leaks group membership across the split; Name is near-unique and offers a tree nothing but memorisation. Both were dropped rather than engineered around.

One split, nine models

A single stratified 80/20 split, random_state=42, reused for every candidate. Decision tree, random forest, gradient boosting, XGBoost and LightGBM, then hard, soft and weighted (1:2:3:4) voting over the first four.

— train — validation

Randomised search over LightGBM

30 draws from a nine-dimensional grid with 5-fold CV. Randomised search is the right tool here: the grid has 26,244 combinations and most dimensions barely matter, so random draws cover the ones that do far more efficiently than an exhaustive sweep.

Honest limits

What was left on the table.

  • Cabin was dropped, not decomposed. It encodes deck, number and side, and the deck/side split is a well-known source of signal on this dataset. Dropping it was the safe call, not the best one.
  • No group features. PassengerId encodes travel groups; group size and whether a companion was transported are strong predictors and are unused here.
  • Tuning selected on CV, reported on holdout. The 2.7-point gap is measured and disclosed, but a nested CV would remove it rather than document it.
  • 16.4% of training rows were discarded by dropping any row with a residual missing value — 1,428 passengers the Unknown sentinel could have retained.
  • The ensembles were never tuned. They combine default-parameter learners, so their failure to beat a single model is only evidence about untuned ensembles.

Next

Where it goes from here.

  • Decompose Cabin into deck, number and side and re-run the benchmark unchanged, to isolate the feature's contribution.
  • Derive group size and group-spend features from PassengerId.
  • Replace the single split with repeated stratified CV so model differences under one point can be distinguished from noise.
  • Stack the tuned learners with a logistic meta-learner on out-of-fold predictions — the one ensemble strategy not yet tried.
