Technical report · Project 02

Tree-based classification on the Spaceship Titanic dataset

A controlled comparison of five tree learners and four voting ensembles, followed by randomised hyperparameter search, threshold optimisation and ONNX export of the winner.

LightGBM 9 models compared RandomizedSearchCV · 30 draws ONNX export Revision 2.0 · 2026
Section 01

Summary

ROC-AUC — held-out validation
Accuracy — at threshold —
F1 — balanced target
Log loss — probability quality

Kaggle's Spaceship Titanic provides 8,693 labelled passengers and asks whether each was transported to an alternate dimension. After a preprocessing pass that fills missing values explicitly and drops two columns on principle, 16 features remain. Nine models were evaluated on one stratified 20% split; gradient boosting led the untuned field at 78.05% and LightGBM followed at 77.70%.

LightGBM was carried forward because it tuned better: randomised search lifted it to 77.84% on the holdout, and a threshold sweep added a further 0.34 points to reach —. Measured on the same split, the tuned model reaches — ROC-AUC — a considerably better result than the accuracy figure alone suggests.

◆ No ensemble beat its best member. All four voting schemes landed between 77.29% and 77.77%, under gradient boosting's 78.05% alone. Correlated errors leave nothing to average away.
▲ Cross-validation overstated performance by 2.7–3.1 points in both tuned configurations, because the search selects its winner on that very score. Section 5 quantifies it.

Section 03

Preprocessing

Three decisions, each with a reason and one with a failed experiment behind it.

Missing values

Every feature is missing roughly 2% of its values, and the gaps are spread thin — most rows are missing at most one field. Two strategies were considered.

Tried: model-based imputation

A classifier was trained to predict the missing categorical values from the observed ones. It reached 72.3% accuracy — meaning more than a quarter of imputed values would have been wrong, and confidently so.

Rejected. Filling 2% of cells with 28% error injects noise that the downstream model cannot distinguish from signal.

Adopted: explicit sentinels

Categoricals are filled with the literal value Unknown, which survives one-hot encoding as its own indicator column. Numerics take the median.

Why it is better. The tree can split on Unknown directly, so if missingness itself carries information the model is free to use it rather than having it papered over.

▲ The bigger cost was row removal, not imputation. After filling, rows that still carried a missing value were dropped, taking training from 8,693 to 7,265 — 1,428 rows, 16.4% of the labelled data. On a dataset this small that is the most questionable decision in the pipeline: the same Unknown-sentinel logic that justified keeping partially-missing rows should have been extended to cover them. The test set was not filtered this way, so training and inference also see slightly different distributions.

Dropped columns

  • Cabin — formatted deck/num/side, and multiple passengers share a cabin. Used raw it is high-cardinality; used as-is across a random split it leaks group membership between train and validation. It was dropped rather than decomposed, which §9 records as the main missed opportunity.
  • Name — almost every value is unique, so any split on it memorises individuals. No surname-group feature was derived.

Encoding

Remaining categoricals were one-hot encoded with pd.get_dummies, dropping the first level to avoid collinearity, yielding the 16-column matrix the model consumes:

Section 04

Model benchmark

Nine candidates, one split, default hyperparameters.

All nine models were fit on the same stratified 80/20 split with library defaults, so the comparison isolates the learner rather than the tuning effort. The four ensembles vote over the five base learners.

What the benchmark says

  • Boosting beats bagging beats a single tree. Decision tree 73.37% → random forest 77.29% → gradient boosting 78.05%. The ordering is textbook, which is mild evidence the pipeline is behaving.
  • XGBoost underperformed LightGBM (76.81% vs 77.70%) at defaults. This is a statement about default hyperparameters, not about the libraries — XGBoost's defaults are more conservative on a dataset this small.
  • No ensemble beat its best member. The best, weighted hard voting at 77.77%, is 0.28 points below gradient boosting alone. Voting helps when members err on different rows; here five tree models trained on identical features make correlated mistakes, so averaging preserves them.
  • The spread is 4.68 points, but the top six sit within 0.8. On a 1,453-row validation set that band is roughly the width of sampling noise, so "which of the top six is best" is not a question this split can answer. LightGBM was carried forward on tuning headroom and export support, not on a claimed win.
Section 05

Hyperparameter search

Two searches, and the gap between cross-validation and reality.

Gradient boosting — exhaustive grid

GridSearchCV over 162 combinations with 5-fold CV reached 80.23% cross-validated accuracy but only 77.15% on the holdout — worse than its own untuned 78.05%. Tuning made it fit the folds better and the unseen data worse.

LightGBM — randomised search

The LightGBM grid has 26,244 combinations, so an exhaustive sweep is impractical. RandomizedSearchCV drew 30 configurations with 5-fold CV, which is the efficient choice when only a few hyperparameters matter: random draws sample many distinct values along the important axes rather than exhausting the unimportant ones.

▲ The search converged on conservative settings. 100 estimators, 31 leaves, unbounded depth, no subsampling and almost no regularisation — essentially a small, plain model. On 5,812 training rows with 16 features, extra capacity buys overfitting rather than accuracy, and the search discovered that on its own.

The cross-validation gap

Cross-validated accuracy against held-out accuracy for both tuned models.

Gradient boostingGridSearchCV, 162 combos 80.23%77.15%−3.08

Both gaps point the same way, and the reason is structural rather than accidental. The search reports the CV score of the configuration it chose because that score was highest. Across 30 (or 162) noisy estimates, the maximum is biased upward: part of the winning score is genuine quality and part is a favourable fold assignment. The holdout was never used for selection, so it carries no such bias, and it is the number quoted throughout this site.

✓ The structural fix is nested cross-validation — an inner loop to select, an outer loop to estimate. It costs roughly k× the compute and removes the bias rather than measuring it after the fact. On a dataset this size that is entirely affordable, and it is the first improvement this pipeline should get.
Section 06

Threshold optimisation

Why 0.5 was not the right cut even on a balanced target.

predict() thresholds probabilities at 0.5 by default. Sweeping every cut from 0.01 to 0.99 against validation accuracy shows the optimum sits lower: 

probs = model.predict_proba(X_val)[:, 1]
best = max(((t / 100, accuracy_score(y_val, probs >= t / 100))
            for t in range(1, 100)), key=lambda p: p[1])
# → threshold 0.42, accuracy 0.7818

Five additional correct predictions out of 1,453 — real, free, and reproducible, but not a headline.

What it means

An optimum below 0.5 says the model systematically under-predicts the positive class. The peak is also broad and flat, which matters more than its height: a sharp peak would mean the threshold was fitted to validation noise and would not transfer. A plateau means the choice is robust.

Section 07

Evaluation

Measured on — held-out passengers by reloading the persisted model.

AUC — against — accuracy is the most interesting number in this report. The model ranks passengers considerably better than it labels them, which means the remaining errors are concentrated near the decision boundary rather than spread across confident predictions. For any use that consumes a ranked list rather than a hard label, the model is materially better than the accuracy headline suggests.

Precision —, recall —. The sub-0.5 threshold buys recall at precision's expense, which is the correct trade only if false negatives are the costlier error — on a Kaggle accuracy metric they are equally costly, so the gain here comes from the calibration shift rather than the asymmetry.

CryoSleep_True alone carries 33.8% of total gain — more than three times the next feature. The five onboard-spending columns follow and together account for roughly 45%, but much of that is the same signal arriving a second time: a passenger in cryosleep cannot spend, so all-zero spending is a near-perfect proxy for the cryosleep flag. The two blocks are substantially redundant, which is why the model needs so little capacity to reach its ceiling.

Everything else is minor. HomePlanet_Europa at 6.4% is the only remaining feature above 5%, and Age, VIP and destination contribute little — consistent with the benchmark finding that all five learners converge to within a point of each other.

Section 08

ONNX deployment

Exporting the model so it runs without Python.

The tuned model and its threshold are persisted together with joblib, then converted to ONNX. One conversion detail is worth recording: the converter rejects numpy.bool_ class labels, so the class metadata is rewritten on a deep copy before export — the copy keeps the original estimator untouched. 

model_for_onnx = copy.deepcopy(rs.best_estimator_)
model_for_onnx._classes = np.array([0, 1])   # bool_ → int64

onnx_model = convert_lightgbm(
    model_for_onnx, initial_types=[("float_input", FloatTensorType([None, 16]))])

Section 09

Limitations

Cabin was dropped, not decomposed

Splitting it into deck, number and side is the single highest-value unexploited feature on this dataset. Dropping it avoided a leakage risk but forfeited real signal; decomposing it while grouping cabin-mates within a fold would get both.

No group features

PassengerId is formatted gggg_pp — group and position. Group size, group spend and whether a travelling companion was transported are all derivable and all unused.

One split decides everything

A single 1,453-row validation set has a standard error near one percentage point, which is wider than the gap separating the top six models. Repeated stratified CV would make those comparisons meaningful.

Ensembles were never tuned

The voting schemes combine default-parameter learners, so their failure to beat a single model is evidence about untuned ensembles only. Stacking tuned models on out-of-fold predictions remains untested.

Selection and reporting are entangled

The threshold was chosen on the same validation set that reports the final accuracy, so the 78.18% carries a small upward bias of its own — smaller than the CV gap, but present.

16.4% of training rows were discarded

Dropping every row with a residual missing value cost 1,428 of 8,693 labelled passengers. Extending the Unknown sentinel to those columns would recover them, and on a dataset this size that is likely worth more than any further tuning.

No competition leaderboard score

Predictions are generated for the test set but no public leaderboard result is recorded here, so the true generalisation estimate is the holdout number and nothing stronger.

Reproduction
